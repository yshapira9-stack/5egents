# מה צריך ממך כדי שהמערכת של דני תעבוד מלא

המערכת מוגדרת ומוכנה (ה-playbook, הזרימה, המיתוג, הלידים). מה שחסר זה **חיבורים
חיצוניים שדורשים פרטי גישה ממך**. להלן הרשימה המלאה, מסודרת לפי עדיפות.

---

## 1. וואטסאפ — הלב של דני 🟥 חובה

✅ **הוחלט (תשובת fixdigital, 2026-06-16): דני רץ על fixdigital במודל
webhook-ממסר — לא צריך ספק BSP נפרד.** אין גישה גולמית (Token/Phone Number ID)
כי המספר מנוהל אצלם, אבל מותר להריץ סוכן AI חיצוני כך:

```
לקוח → הודעה בוואטסאפ → fixdigital → webhook לדני → דני מייצר תשובה
   → דני מחזיר דרך ה-API של fixdigital → נשלח ללקוח
```

זה מאחד וואטסאפ + CRM אצל ספק אחד. מה שאושר על ידם:
- ✅ **שליחת תמונות** ללקוח נתמכת (תמונות קונספט של יובל).
- ✅ **ליד אוטומטי** — כל הודעה נכנסת נכנסת כליד עם `channelid=whatsapp`.
- ✅ **בוט + נציג** — מעבר בלחיצה לנציג אנושי באותה שיחה (handoff דני→יניב).
- ⚠️ **קבוצות אוטומטיות לא נתמכות** (מגבלת Meta) — `group.mjs` שולח לכל אחד
  בנפרד, או שיניב פותח קבוצה ידנית.
- ⚠️ **הודעות יזומות** דורשות תבנית מאושרת Meta; תשובה תוך חלון 24ש' מפניית
  לקוח = חופשי. רוב שיחת דני בחלון החינמי (הלקוח פונה ראשון).

🔧 **דורש שרת עם כתובת ציבורית** לקבלת ה-webhook → זו המטרה של ה-VPS (ראה דיון חומרה).

📋 **תיעוד התקבל (2026-06-17)** — שני מדריכים:
- אאוטבאונד (פיקס → דני): https://info.fixdigital.co.il/docs/אוטומציה-לשליחת-פניות-ב-api-מ-fixdigital-למערכת-חי/
  מוגדר ב-**ממשק של פיקס** (אוטומציה): GET/POST, 2 שדות header מותאמים לאימות,
  שדות דינמיים + `{OTHER_FIELDS}` / `{{OTHER_FIELDS{שדה}}}`. הטריגר לפי סטטוס/מקור/
  אסט/קמפיין. **אנחנו מספקים URL ובוחרים אילו שדות יישלחו.**
- אינבאונד (דני → פיקס): https://info.fixdigital.co.il/docs/receiveapi/ → `lead/addApi`.

✅ **פורמט ה-webhook אומת (2026-06-18)** מאוטומציה קיימת ("תהליך תכשיטים – וובהוק
לידים", ID 16232): שיטה **POST**, גוף **urlencoded** `name={FULLNAME}&phone={PHONE}&email={EMAIL}`
(+ טוקנים דינמיים נוספים כמו Lead ID), Headers ריקים (פנויים ל-secret שלנו).
ה-URL הנוכחי מצביע ל-**Make.com** (`hook.eu2.make.com/...`) — לידי תכשיטים כבר
זורמים ל-Make. המקלט שלנו (`receive.mjs`) כבר תואם לפורמט הזה.

נותר לבנות בצד שלנו:
- ⬜ **מקלט webhook בפורמט פיקס** — להתאים את `דני/whatsapp/receive.mjs` (שדות גמישים +
  אימות header מותאם). 
- ⬜ **רישום כתובת ה-webhook** בממשק פיקס (אחרי שיהיה VPS ציבורי).
- ⬜ **תבניות Meta** להודעות יזומות (רק אם נשלח מחוץ לחלון 24ש').

מספרים שכבר נשמרו ב-`.env` (לא בריפו, מטעמי פרטיות): מספר העסק
(`WHATSAPP_BUSINESS_NUMBER`), יניב (`YANIV_WHATSAPP`), סטודיו (`STUDIO_WHATSAPP`).

> ⚙️ **הערת קוד:** שכבת `דני/whatsapp/` הקיימת נכתבה למודל Meta Cloud API הישיר
> (Token + Phone Number ID + שליחה ישירה). לפי ההחלטה היא תותאם למודל ה-webhook
> של fixdigital כשיגיע התיעוד הטכני למעלה.

## 2. ערוצי כניסה — המשפך ללקוחות 🟥 חובה (לפחות אחד)

כולם מפנים לאותו מספר וואטסאפ שבו דני מנהל את השיחה:

## 3. CRM — ניהול לידים אמיתי ✅ מחובר (14.7.2026, לתכשיטים)

ה-CRM שלך מתארח ב-**fixdigital.co.il**. ה-API פשוט — לא OAuth2 — אלא מזהי
**נכס/חברה** קבועים שנשלחים כ-query-string. תיעוד:
- יצירת ליד: `POST https://www.fixdigital.co.il/api/v1.2/lead/addApi`
- ליד מוואטסאפ: `POST /api/v1.2/lead/addwhatsapp`
- עדכון סטטוס/סכום: `GET /api/crm/webhook/UpdateLeadStatusOrAmount`
- שליפת לידים: `GET /api/crm/webhook/GetLeads` / `GetLeadsWithFields`
- קודי סטטוס: 4=בטיפול, 6=טוב, 7=פגישה, 8=נשלחה הצעה, 9=נסגר, 10=לא נסגר, 11=לא טוב

⚠️ **עדכון חשוב (14.7.2026):** ההנחה הקודמת (`clientID`/`tenantID`/`projectID`/
`projectTypeID`, ממייל תמיכה) **הייתה שגויה/מיושנת**. הערכים האמיתיים, לפי מה
שמוצג בפועל בממשק פיקס, הם:
- 🆔 `assetId` — מזהה **הנכס הדיגיטלי** (נכסים → "עוזר ai" → מסוג "חיבור API").
- 🆔 `assetTypeId` — סוג הנכס (10 = חיבור API).
- 🆔 `companyId` — מזהה החברה/החשבון.
- 🔢 `channelid` (אופציונלי) — לסימון ערוץ המקור של הליד.
- 🔑 `api_key` (רק לעדכון/שליפת לידים — לא נדרש ליצירה).

**איך משיגים אותם (בפועל, לא דרך תמיכה):** בממשק פיקס → ☰ → **נכסים** →
"רשימת הנכסים הדיגיטליים שלי" → **צור חיבור API חדש** (או פתח קיים) → בטאב
**"CRM"** משייכים תהליך/סטטוס/נציג → בטאב **"חיבור אתר"** מוצגת כתובת ה-API
המלאה של הנכס, ובה שלושת המזהים כפרמטרים קבועים ב-URL.

**לכל קו עסקי (עסק) — נכס API נפרד**, כדי שלידים ינותבו לתהליך הנכון: הנכס
"עוזר ai" מחובר לתהליך **"תכשיטים"**, נציג **"מכירות תכשיטים"** — משרת את
**דני**. ✅ **גם יהודה מחובר (14.7.2026)** — נכס "יהודה עוזר לתחום הלימודים
והסדנאות" מחובר לתהליך **"לימודים"**, נציג **"מכירות לימודים"**. שני
החיבורים נבדקו חי ואומתו בממשק. הערכים המדויקים (assetId/assetTypeId/
companyId — מהווים אימות בפועל ל-API) חיים **רק ב-`.env` המקומי** (מוחרג
מגיט, לא כאן) — `CRM_ASSET_ID*` לדני, `CRM_ASSET_ID*_YEHUDA` ליהודה;
`create-lead.mjs` בוחר אוטומטית לפי תיקיית קובץ הליד.

**אימות ה-webhook (פיקס → דני, לקבלת הודעות נכנסות):** פיקס אמרו "מצידנו אין
דרישות מיוחדות" → אנחנו בוחרים את ה-secret וה-header בעצמנו (כבר נתמך ב-
`receive.mjs` דרך `FIXDIGITAL_WEBHOOK_SECRET`) — זה עדיין לא הוגדר.

✅ **שכבת `דני/crm/` מחוברת וחיה** — `.env` מולא בערכי הנכס (ראה מעלה), נבדק
גם ב-`--dry-run` וגם בפועל (ליד בדיקה נוצר ואומת בממשק — 14.7.2026). פרטים:
`דני/crm/README.md`.

**מקורות תיעוד:** https://info.fixdigital.co.il/docs/receiveapi/ ·
https://api-explainer-buddy-fixdigital.lovable.app/ · תמיכה: support@fixdigitalcrm.com
