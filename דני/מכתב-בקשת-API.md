# מכתב בקשת גישת API — CRM + WhatsApp

מכתב מוכן לשליחה לספק (fixdigital), המבקש את פרטי הגישה לחיבור ה-CRM ולחיבור
ה-WhatsApp Business. ראה גם [מה-צריך-ממך.md](מה-צריך-ממך.md) לרשימת הדרישות המלאה.

---

**הנדון: בקשת גישת API — מערכת CRM וחיבור WhatsApp Business**

שלום רב,

אנחנו מקימים מערכת אוטומטית לניהול פניות לקוחות, ואשמח לקבל מכם את פרטי הגישה
הדרושים כדי לחבר אותה. שני חיבורים נחוצים לנו:

**1. גישת API ל-CRM**

המערכת תיצור באופן אוטומטי לידים ואנשי קשר ב-CRM שלנו (המתארח אצלכם,
fixdigital.co.il). לצורך כך נדרשים:

- **פרטי הזדהות OAuth2** — `client_id` ו-`client_secret` עם scope הכולל `api`
  (או API token קבוע, אם זו השיטה שאתם תומכים בה).
- **כתובת ה-API** — ה-base URL של ה-API, ונקודת ה-token (נראה לי שזה
  `auth.fixdigital.co.il/connect/token` — נשמח לאישור).
- **תיעוד ה-API** — בעיקר איזה endpoint יוצר Lead / Contact, ואילו שדות הם
  חובה ביצירה.

**2. חיבור ל-WhatsApp Business API**

אנחנו רוצים לחבר את מספר ה-WhatsApp Business שלנו למערכת, כך שהיא תוכל לקבל
ולשלוח הודעות אוטומטית. נדרשים לנו:

- **Access Token** של ה-WhatsApp Business API.
- **Phone Number ID** ו-**WhatsApp Business Account ID** (המזהים מלוח הבקרה, לא
  המספר עצמו).
- אם אתם מספקים את שירות הוואטסאפ — נשמח לדעת **איזה ספק עומד מאחורי החיבור**
  (Meta Cloud API / Twilio / 360dialog וכו'), ואת **תיעוד ה-API** הרלוונטי.
- בנוסף — האם החיבור תומך ב**פתיחת קבוצות WhatsApp באופן אוטומטי**? זה חשוב
  לתהליך אצלנו.

אם הוואטסאפ מנוהל אצל ספק אחר ולא אצלכם — אשמח שתפנו אותי לגורם הנכון.

תודה רבה, ואשמח לכל הכוונה.

## עדכון — תשובת המשך אחרי שקיבלת מ-fixDigital את התיעוד

הם הבהירו שהוואטסאפ לא מנוהל אצלם (אלא רק קליטת לידים), ושה-CRM API עובד עם
`api_key` + מזהי חשבון (לא OAuth2). הנה נוסח מענה מוכן לשליחה:

---

**הנדון: בקשת פרטי גישה ל-CRM API + שאלה על אוטומציית WhatsApp**

שלום, תודה על התיעוד.

**1. ל-CRM API** — ראיתי את ה-endpoints (`/api/v1.2/lead/addApi`,
`UpdateLeadStatusOrAmount` וכו'). אשמח לקבל את הערכים הספציפיים של החשבון שלי כדי
להתחבר:

- `api_key` (לעדכון ושליפת לידים).
- `clientID`, `tenantID`, `projectID`, `projectTypeID`.
- `channelid` (אם רלוונטי) — איך אני יוצר/מקבל ערוץ כדי לסמן את מקור הליד.

**2. לגבי WhatsApp** — הבנתי שכדי לקלוט פניות אני שולח אליכם ליד דרך ה-receive API.
שאלה חשובה: האם הוואטסאפ שאתם מנהלים תומך ב**מענה אוטומטי / בוט** (קבלת הודעה
מהלקוח + שליחת תשובה ותמונות בחזרה אוטומטית), או שזה מיועד רק לקליטת פניות ולמענה
ידני של נציג? אני מעוניין בשיחה דו-כיוונית אוטומטית, ורוצה להבין אם זה אפשרי אצלכם
או שאני צריך ספק WhatsApp Business נפרד.

## עדכון 2 — בקשת התיעוד הטכני לחיבור הבוט (אחרי אישור מודל ה-webhook)

הם אישרו שאפשר להריץ סוכן AI חיצוני דרך webhook + API שלהם (לא גישה גולמית).
הנה נוסח מענה לבקשת הפרטים הטכניים הדרושים כדי לבנות את החיבור:

---

**הנדון: תיעוד טכני לחיבור הבוט שלי דרך ה-Webhook**

שלום, תודה על ההסבר — מודל ה-webhook מתאים לי בדיוק. כדי לבנות את החיבור אשמח
לקבל את התיעוד הטכני:

1. **פורמט ה-Webhook** — מה מבנה ה-payload (JSON) שאתם שולחים לשרת שלי כשמגיעה
   הודעה נכנסת מלקוח? (כולל איך מזוהה השולח, תוכן ההודעה, וקובצי מדיה אם יש.)
2. **endpoint השליחה** — לאיזו כתובת אני שולח את התשובה של הבוט (טקסט + תמונות),
   באיזה פורמט, ואיך מאמתים את הבקשה (ה-`api_key` הקיים? טוקן נפרד?).
3. **רישום כתובת ה-Webhook** — איך אני רושם אצלכם את כתובת השרת שלי שתקבל את
   ההודעות הנכנסות.
4. **תבניות Meta** — מה התהליך לאישור תבניות להודעות יזומות (Outbound).

בנוסף — אשמח להבין מצוות המכירות את **המחיר והמודל** לתצורה הזו (בוט AI חיצוני
דרך webhook + CRM).

## עדכון 3 — עדכון/הוספת הערה ללקוח קיים לפי מספר טלפון (לא יצירת ליד חדש)

---

**הנדון: זיהוי לקוח קיים לפי טלפון + הוספת הערה (לא יצירת ליד חדש)**

שלום רב,

יש לנו כבר חיבור פעיל ליצירת לידים דרך `lead/addApi` (עם `assetId`/`assetTypeId`/
`companyId`). כעת אנחנו בונים תהליך נוסף: מקור נתונים חיצוני שמתעדכן מדי פעם
עם מידע על לקוחות **קיימים** אצלנו, ואנחנו רוצים שכל עדכון כזה יתווסף כהערה
אצל הלקוח הקיים — מזוהה לפי **מספר הטלפון** שלו, בלי ליצור רשומה כפולה.

שאלות:

1. אם שולחים `lead/addApi` עם מספר טלפון שכבר קיים אצלכם כלקוח/ליד — האם הוא
   מזוהה אוטומטית והרשומה מתעדכנת (למשל ההערה מתווספת לקיים), או שנוצרת בכל
   פעם רשומה חדשה/כפולה?
2. אם נוצרת כפילות — האם קיים אצלכם endpoint נפרד לחיפוש לקוח/ליד לפי מספר
   טלפון, ו/או להוספת הערה לרשומה קיימת (בדומה ל-`UpdateLeadStatusOrAmount`,
   אבל עבור שדה ההערות ולא סטטוס/סכום)?
3. אם אין endpoint כזה כרגע — האם אפשר להוסיף אחד, או שיש דרך אחרת מומלצת
   מצידכם להשגת אותה תוצאה (עדכון הערה ללקוח קיים לפי טלפון, ללא כפילות)?

תודה רבה!

### ✅ תשובת פיקס (התקבלה)

1. **כל פנייה ל-`lead/addApi` מזוהה לפי מספר טלפון** — אם קיים כבר ליד/לקוח
   עם אותו טלפון, הפנייה **לא** יוצרת כפילות אלא משויכת לכרטיס הלקוח הקיים.
   הפרטים החדשים מעדכנים את הקיימים, והפרטים הקודמים נשמרים ב**היסטוריית
   השינויים** של הכרטיס. → המשמעות: המנגנון הקיים (`דני/crm/create-lead.mjs`)
   מתאים גם ל"עדכון לקוח קיים לפי טלפון", לא רק ליצירת ליד חדש.
2. **קיים API לקריאת ערכי השדות של לקוח לפי מספר טלפון.** שם ה-endpoint/
   שיטת האימות טרם פורטו על ידם — אם לא קיים ליד עם הטלפון שנשלח, מוחזר
   `{"Error": "Lead not found"}`. **פתוח:** לבקש מפיקס את הפרטים המדויקים
   (endpoint, method, פרמטרים, אימות) אם נרצה לקרוא/לאמת נתונים ולא רק לדחוף.

## עדכון 4 — קודי סטטוס לתהליך הייצור + פרטי `UpdateLeadStatusOrAmount`

---

**הנדון: קודי סטטוס לשלבי הייצור + פרטי ה-API לעדכון סטטוס/הזמנה**

שלום רב,

בהמשך לחיבור הקיים (`lead/addApi`) — אנחנו רוצים להעביר גם עדכוני **הזמנות**
קיימות: מספר הזמנה, סכום, פירוט, ובעיקר **שלב הייצור הנוכחי** (למשל יציקה,
הדפסה, שיבוץ, ציפוי וכו') כפי שהוא מוגדר אצלכם בתהליך המשויך לנכס שלנו —
**לא** מדובר בסטטוס תהליך המכירה, אלא בשלבי הייצור הפיזיים של התכשיט.

שאלות:

1. מהם קודי/שמות הסטטוס המדויקים של שלבי הייצור (יציקה/הדפסה/שיבוץ/ציפוי
   וכל שלב נוסף) המוגדרים בתהליך המשויך לנכס שלנו בפיקס?
2. מהם הפרמטרים המדויקים של `GET /api/crm/webhook/UpdateLeadStatusOrAmount`
   (method, שמות פרמטרים, אימות) — והאם אפשר לזהות את הליד/הלקוח לפי מספר
   טלפון, כמו ב-`addApi`?
3. האם השדות `ORDER_ID`, `ORDER_AMOUNT`, `ORDER_DETAILS` (שראינו כפרמטרים
   אופציונליים ב-`lead/addApi`) פעילים בפועל על החשבון שלנו?

תודה רבה!
